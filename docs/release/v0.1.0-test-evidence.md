# v0.1.0 release-candidate evidence

Date: 2026-08-01

This record covers reproducible local source/build gates and a bounded physical-device compatibility check. Under [ADR 0003](../adr/0003-early-public-release-policy.md), this evidence can support an explicitly scoped early public release; it does not constitute broad device or accessibility certification.

## Reproducible build

Environment:

- Temurin OpenJDK 17.0.8
- Gradle wrapper 9.6.1
- Android Gradle Plugin 9.3.1
- Android compile SDK 36.1, target SDK 36, minimum SDK 26
- Kotlin/Compose compiler plugin 2.3.21 and Compose BOM 2026.06.00

The repository wrapper downloaded the canonical Gradle distribution successfully and validated the committed SHA-256. No China mirror was required. With the dependency cache warmed, this repository-owned command passed offline with strict verification:

```bash
# Configure JDK 17 and ANDROID_HOME for your machine first.
./gradlew --offline --console=plain --dependency-verification=strict \
  test \
  :app:assembleDebug \
  :app:assembleDebugAndroidTest \
  :app:lintRelease \
  :app:assembleRelease
```

The final post-review committed candidate passed this complete gate. Its exact source revision, task/timing result, JVM-test count, lint summary, and APK hashes are recorded together in the ignored local manifest `build/release-evidence/SHA256SUMS` so the evidence can be regenerated without changing the source revision it identifies.

## Automated checks

- 74 JVM tests passed with zero failures/errors, including redacted and explicit-unredacted snapshot/log encoding, stable redacted log aliases, exact raw-value retention only for opted-in sessions, channel mapping, history geometry, scan lifecycle serialization, connection selection, and privacy transformation.
- Nine Compose instrumentation tests compiled and the instrumentation APK assembled. New coverage verifies that disabling report redaction requires confirmation and that an unredacted payload receives a sensitive exact preview plus a dedicated share action.
- Release lint completed with zero Error/Fatal issues and 11 warnings: eight pinned-version/update notices plus three non-blocking compatibility notices.
- `git diff --check` passed.
- A source scan found no `INTERNET` permission, Java/network client endpoint, socket/URL client, raw `Log.*`, or `println` call in production source.

## Artifact evidence

The build produces the locally installable debug APK, the instrumentation APK, and a shrunk unsigned release candidate at their standard paths under `app/build/outputs/apk/`. Build artifacts are ignored by Git. Android Gradle Plugin embeds source-control revision metadata, so committing a checksum inside the same revision can make that checksum stale on the next build. The permanent maintainer process signs and verifies the exact post-merge candidate outside Git; artifact hashes belong in the corresponding GitHub Release.

## Release APK static audit

The packaged release requests only:

- `ACCESS_COARSE_LOCATION`
- `ACCESS_FINE_LOCATION`
- `ACCESS_NETWORK_STATE`
- `ACCESS_WIFI_STATE`
- `CHANGE_WIFI_STATE`
- AndroidX's app-signature `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`

It has no Internet, local-network, storage, background-location, VPN, notification, usage-access, or broad package-query permission. Backup and cleartext traffic are disabled.

`MainActivity` is the only app-defined exported component. AndroidX contributes a non-exported startup provider and an exported profile-installer receiver protected by `android.permission.DUMP`; ordinary third-party apps cannot invoke that receiver.

## Physical-device gate

The original release-candidate build had no attached Android device. A later bounded check used one OPPO PMX110 running Android 17 (API 37) at 1272 x 2772 and 560 dpi. API 37 is a forward-compatibility lane, not one of the declared API 26–36 release targets.

The current debug host installed without clearing data. Android's Unified Test Platform then hit OEM package-installer error `-99` while installing the separate test APK and its cleanup removed the debug host package. Installing the same current debug and test APKs directly and invoking `AndroidJUnitRunner` completed all nine instrumentation tests successfully in 9.906 seconds. This records an OEM test-runner installation exception, not a test failure.

The exact signed public RC APK then installed successfully. Pulling the installed base APK back from the device produced the same SHA-256 as the published artifact, `b6388c47ed3d3e7da573143e2195a86f7ca1fd5885c5bce4b1dbf93e2d772af4`. The installed APK remained non-debuggable, verified with APK Signature Schemes v2 and v3, and had signing-certificate SHA-256 `3d170c6970999581227c7f0f4423564310ea2afd9b8d38d72d046a4c314b489f`.

The release cold-launched successfully with no observed crash or ANR. Track and Settings were inspected natively in dark mode. The report-redaction setting was enabled by default; opting out displayed the full sensitive-data warning; an unredacted log froze and labelled its session mode; its JSON preview required **Share unredacted**; restoring redaction made the next log session redact identifiers and use the ordinary **Share** action. No report was shared. The unredacted in-memory session was cleared, and redaction was restored before the check ended.

The installed manifest still lacked `INTERNET`, and a point-in-time `/proc/net/tcp*` check found no rows owned by the app UID. This is supporting evidence only, not a substitute for the required external traffic capture. The OEM also rejected ADB runtime-permission revocation with `SecurityException`, so permission denial/revocation remains a manual device-matrix item. A later all-destination screenshot pass was interrupted by the lock screen; blank captures were rejected as evidence.

Every direct ADB tap in this bounded check had a five-second response wait. The maintainer accepted the disclosed residual risk and authorized promotion of the byte-identical, device-tested RC under ADR 0003. The API 26–36 device classes, permission states, remaining destinations and display modes, TalkBack, Switch Access, performance, battery, reproducibility, and external-network checks remain a non-blocking public validation backlog and must not be claimed as passed.
