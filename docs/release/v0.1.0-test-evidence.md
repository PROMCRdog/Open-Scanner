# v0.1.0 release-candidate evidence

Date: 2026-07-31

This record covers reproducible local source/build gates. It does not convert the candidate into a final release: physical-device installation, native UI/runtime inspection, and the final independent review remain separate gates.

## Reproducible build

Environment:

- Temurin OpenJDK 17.0.8
- Gradle wrapper 9.5.0
- Android Gradle Plugin 9.3.0
- Android compile SDK 36.1, target SDK 36, minimum SDK 26
- Kotlin/Compose compiler plugin 2.3.21 and Compose BOM 2026.06.00

The repository wrapper downloaded the canonical Gradle distribution successfully and validated the committed SHA-256. No China mirror was required. With the dependency cache warmed, this repository-owned command passed offline with strict verification:

```bash
export JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home
export ANDROID_HOME="$HOME/Library/Android/sdk"
./gradlew --offline --console=plain --dependency-verification=strict \
  test \
  :app:assembleDebug \
  :app:assembleDebugAndroidTest \
  :app:lintRelease \
  :app:assembleRelease
```

The final post-review committed candidate passed this complete gate. Its exact source revision, task/timing result, JVM-test count, lint summary, and APK hashes are recorded together in the ignored local manifest `build/release-evidence/SHA256SUMS` so the evidence can be regenerated without changing the source revision it identifies.

## Automated checks

- 30 JVM tests passed with zero failures/errors: channel mapping, legacy/unknown security parsing, overlap analysis, timestamp history pruning and global caps, paused/stale/empty chart geometry, proportional spectrum-width truthfulness, scan lifecycle serialization, deterministic physical-Wi-Fi selection, snapshot connection refresh, privacy transformation, and redacted export.
- Four Compose instrumentation tests compiled and the instrumentation APK assembled; they were not run because the connected device rejected standard ADB installation. Regression coverage verifies that cached data cannot hide a current permission block and that blocked Tools states withhold stale connection fields.
- Release lint completed with zero Error/Fatal issues. Its 15 warnings are 13 pinned-version/update notices plus two non-blocking launcher compatibility notices (the API-26 adaptive resource qualifier and absence of an optional monochrome themed icon).
- `git diff --check` passed.
- A source scan found no `INTERNET` permission, Java/network client endpoint, socket/URL client, raw `Log.*`, or `println` call in production source.

## Artifact evidence

The build produces the locally installable debug APK, the instrumentation APK, and a shrunk unsigned release candidate at their standard paths under `app/build/outputs/apk/`. Build artifacts are ignored by Git. Android Gradle Plugin embeds source-control revision metadata, so committing a checksum inside the same revision can make that checksum stale on the next build. Instead, the final post-commit build writes its HEAD and SHA-256 values to the ignored local manifest `build/release-evidence/SHA256SUMS`; the handoff reports those values directly. The release APK is intentionally unsigned and is not a distributable production binary.

## Release APK static audit

The packaged release requests only:

- `ACCESS_COARSE_LOCATION`
- `ACCESS_FINE_LOCATION`
- `ACCESS_NETWORK_STATE`
- `ACCESS_WIFI_STATE`
- `CHANGE_WIFI_STATE`
- AndroidX's app-signature `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`

It has no Internet, local-network, storage, background-location, VPN, notification, usage-access, or broad package-query permission. Backup and cleartext traffic are disabled.

`MainActivity` is the only app-defined exported component. AndroidX contributes a non-exported startup provider and an exported profile-installer receiver protected by `android.permission.DUMP`; ordinary third-party apps cannot invoke that receiver.

## Physical-device gate

The connected Xiaomi/HyperOS device returned `INSTALL_FAILED_USER_RESTRICTED: Install canceled by user` for the standard `adb install -r` command. No device security setting was changed or bypassed. See `docs/qa/device-install-blocker.md`.

The final tag remains blocked until the device owner enables the normal **Install via USB** path, after which installation, instrumentation, screenshots, accessibility checks, and the five-second wait after every tap can be completed.
