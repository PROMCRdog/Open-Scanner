# Open Scanner v0.2.0 — Truthful 5-second refresh

Open Scanner v0.2.0 is an early public release of the passive, local-only Android Wi-Fi analyzer. Its main addition is a foreground **5 s request mode** that is available only when Android explicitly reports Wi-Fi scan throttling as off.

## What is new

- Exact refresh choices are 5, 10, 15, 30, and 60 seconds; 30 seconds remains the default.
- The app permits only one scan request in flight, coalesces manual refreshes, recovers from a stalled request after 15 seconds, and stops fast requests when paused or backgrounded.
- If five seconds was saved and Android later reports throttling on or unavailable, the app persists and schedules the 30-second fallback after capability discovery.
- Charts, history, sequence IDs, and logs advance only for newly timestamped scan evidence. Cached, rejected, unchanged, and timed-out cycles remain visibly stale instead of creating fake samples.
- English and Simplified Chinese now cover semantic hidden/private network names, connection evidence, security profiles, Wi-Fi generations, fast-mode explanations, and dynamic version copy.

## Privacy and safety boundary

- No `INTERNET` permission, telemetry, ads, accounts, background service, wake lock, port scanning, LAN probing, password handling, or one-second mode was added.
- Open Scanner does not join networks. Android owns connection and protected Developer options.
- Report redaction remains on by default. Unredacted sharing still requires an explicit warning and review of the exact payload before Android's share sheet opens.

## Verification scope

- 107 JVM tests and 14 Compose instrumentation tests passed with zero failures or skips.
- Release lint completed with zero errors. Strict dependency verification, debug/test APK assembly, and unsigned release assembly passed with the build cache disabled and every task rerun.
- The signed candidate installed in place and returned a process-level cold start on an authorized OPPO PMA120 running Android 16 / API 36. Its installed APK was byte-identical to the candidate.
- Final independent review accepted the code and corrected signed candidate with no P0-P3 findings. Publication remains blocked until CI passes and the secure test device is unlocked so the exact candidate can complete the throttle ON/OFF, two-minute cadence trace, automatic fallback, lifecycle/manual-refresh, migration, and battery/cadence-disclosure protocol, plus the redacted and explicit-unredacted report flows.

This is not broad compatibility certification. API 26–36 device diversity, additional OEMs, full accessibility tooling, large text, RTL, rotation/multi-window, extended battery/performance testing, traffic capture, and reproducible-build comparison remain public follow-up work.

Disabling Android scan throttling removes Android's standard quota for local testing; it does **not** guarantee that the Wi-Fi chipset or OEM completes a fresh scan every five seconds. On API 26–28, and whenever Android cannot report the setting, five-second mode stays disabled. Faster requests may increase battery use.
