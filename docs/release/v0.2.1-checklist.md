# v0.2.1 release checklist

Status: **published and verified.** The Spectrum implementation, strict local build, JVM tests, API 36 emulator UI tests, pull-request and merged-main CI, permanent signing, exact physical installation, artifact identity, redacted/unredacted preview boundary, bounded Spectrum QA, annotated tag, release upload, and fresh public-download verification have passed. The v0.2.0 in-place-upgrade repeat, independent review, and broader physical coverage remain visible non-blocking compatibility work under ADR 0003.

This checklist applies the early public release policy in [ADR 0003](../adr/0003-early-public-release-policy.md) to the Spectrum display-scaling update. A checked item is backed by the bounded evidence in [v0.2.1-test-evidence.md](v0.2.1-test-evidence.md); it is not a claim of broad device certification.

## Product behavior

- [x] Spectrum displays every observed AP in the selected channel group by default; there is no fixed four-network truncation.
- [x] A per-group multi-select control can show or hide individual curves, restore all curves, or keep only the focused AP.
- [x] A separate radio control in the same selector chooses exactly one focused AP and makes a newly focused AP visible without changing the Android Wi-Fi connection; the single-choice heading, cyan focused row/badge, and muted-but-enabled alternatives make the rule visible.
- [x] The focused AP remains pinned so the chart, selected-AP summary, and overlap analysis do not silently refer to different APs.
- [x] The selector reports the exact shown/total count and states that hidden curves still contribute to full-snapshot overlap analysis.
- [x] Cyan focus and green Current Wi-Fi roles remain independent, including a green peak marker when both roles refer to one AP.
- [x] The exact Current Wi-Fi badge appears in Scan, the Spectrum selector, and the Track network picker.
- [x] A bonded footprint remains centered on Android's reported segment center while a dashed marker and copy identify the primary channel.
- [x] English and Simplified Chinese resources and README coverage remain synchronized.

## Implementation and automated/static evidence

- [x] Version is `3` / `0.2.1`, and About continues to read `BuildConfig.VERSION_NAME`.
- [x] Display filtering is an in-memory UI transformation; it adds no scan loop, permission, network request, background component, or identifier persistence.
- [x] All 119 JVM tests pass with zero skips, failures, or errors.
- [x] All 17 Compose instrumentation tests pass on the Android 16 / API 36 `OpenScannerQA` emulator.
- [x] A cache-independent strict build reran 362 tasks covering JVM tests, debug/test APKs, release lint, and unsigned release assembly.
- [x] Release lint passes without errors; remaining warnings are recorded and `git diff --check` passes.
- [ ] Independent read-only review accepts the final candidate revision.
