# v0.2.0 release checklist

Status: **not release-ready**. Implementation, the local static/build gate, and independent read-only source review passed on source revision `e9c4f45`; permanent signing, upgrade installation, and v0.2.0 physical-device behavior QA remain pending.

This checklist applies the early public release policy in [ADR 0003](../adr/0003-early-public-release-policy.md) to the conditional fast-refresh decision in [ADR 0004](../adr/0004-conditional-fast-scan-cadence.md). A checked documentation item is not evidence that the corresponding runtime behavior passed.

## Decision and documentation baseline

- [x] Five-second mode is defined as a foreground request cadence, not a guaranteed hardware scan cadence.
- [x] Supported values are fixed at 5, 10, 15, 30, and 60 seconds; 30 seconds remains the default/fallback and no one-second mode is included.
- [x] Eligibility requires an explicitly discovered throttle-off state; throttle-on and unavailable states disable five seconds.
- [x] A saved five-second value automatically resets to 30 seconds after capability discovery if it becomes ineligible.
- [x] The scope excludes new permissions, `INTERNET`, a background service/worker, wake locks, and a second scan loop.
- [x] The English and Simplified Chinese documentation baselines no longer describe localization as future work.

## Implementation and automated/static evidence

- [x] Version is `2` / `0.2.0`, and About reads `BuildConfig.VERSION_NAME`.
- [x] Preference validation accepts only the five supported values and resets every other persisted value to 30 seconds.
- [x] One monotonic scheduler enforces one in-flight request, coalesces manual refresh, recovers after 15 seconds, reschedules after relevant state changes, and stops outside the foreground.
- [x] Fresh broadcasts advance observation identity/history; rejected, non-updated, unchanged, cached, and timed-out cycles do not create new samples.
- [x] Five-second eligibility, accessible unavailable explanations, battery/OEM warning, and automatic 30-second fallback are present in English and Simplified Chinese.
- [x] All 102 JVM tests pass and cover cadence, timeout, overlap prevention, coalescing, lifecycle stop/resume, eligibility, delayed capability discovery, fallback, serialized publication, and truthful freshness.
- [x] Compose test source covers five seconds enabled, disabled for throttle-on/unavailable/unresolved states, selection, dynamic version copy, and accessibility semantics; all 14 instrumentation tests compile into the test APK but have not yet run on v0.2.0 hardware.
- [x] Strict JVM tests, debug assembly, instrumentation assembly, release lint, and unsigned release assembly pass on source revision `e9c4f45`.
- [x] `git diff --check` passes on the intended branch diff.
- [x] An independent read-only source review passes at `e9c4f45` with no remaining P0-P3 code findings; final signed/device evidence remains subject to follow-up verification.
- [x] Packaged manifest/component audit confirms no new permission, no `INTERNET`, and no app-defined service, worker, alarm, or background scan component.
- [x] Dependency review confirms that v0.2.0 adds no dependency for fast refresh.

## Physical-device QA

No Android device was attached when this record was opened. An OPPO PMA120 running Android 16 / API 36 later connected with permanently signed Open Scanner v0.1.0 installed. Every v0.2.0 item below remains unchecked until a verifier-approved candidate is signed with the matching maintainer identity and exercised without replacing that baseline with a mismatched debug build.

- [ ] On an authorized Android 10+ device, throttle ON leaves five seconds visible but disabled with the correct explanation.
- [ ] After throttle OFF, five seconds can be selected and a two-minute redacted request/source-age trace is captured.
- [ ] The trace demonstrates one request at a time and distinguishes fresh timestamps from cached/reused evidence; it does not need to demonstrate a fresh hardware result every five seconds.
- [ ] Switching throttle back ON automatically persists and schedules 30 seconds.
- [ ] Pause/resume, background/foreground, process restart, timeout recovery, and manual-refresh coalescing are exercised without crash or ANR.
- [ ] Upgrade installation from the permanently signed v0.1.0 artifact preserves the expected signing lineage and safely migrates preferences.
- [ ] Battery/performance observations are recorded with the device, OS, duration, and actual result cadence disclosed.
- [ ] Every direct device UI tap is followed by a five-second response wait.

## Artifact and release authorization

- [ ] A permanent maintainer identity signs the exact final non-debuggable candidate outside Git.
- [ ] APK hash, certificate hash, signature schemes, package/version metadata, and source revision are recorded.
- [ ] The byte-identical signed candidate installs and cold-launches on the authorized test device.
- [ ] The release evidence and notes distinguish completed static checks from bounded physical scope and do not promise five-second hardware results.
- [ ] Independent verification findings are resolved and a maintainer explicitly authorizes release.
- [ ] No push, release tag, or publication occurs without explicit authorization.
